# elodin benchmark

Measured on AMD Ryzen 7 PRO 6850U with Radeon Graphics (16 logical cores, 31 GB RAM, Linux 7.0.14-201.fc44.x86_64), elodin 0.1.0.

Mock upstream held at 20ms. DNSSEC off. Each run 10s measured after 2s of warmup, median of 3, 8s idle between runs.

Cores were averaging 2980 MHz when the run finished. This is a 15 W laptop part that cannot hold its boost clock through the whole matrix, so treat the absolute figures as the shape of the thing rather than a specification.

Each section was run separately (`-only <section>`), from a cooled machine, and the results concatenated. Run back to back the later sections come out 20–30% slower purely from heat — which is also why the throughput figures in one section should not be compared with those in another. Comparisons within a section are sound; the whole point of the ordering inside each one is that it holds the machine constant.

## Past capacity

Cache misses from 6,000 clients at once, against a worker pool that can carry about 6400/s.

| max_pending | served | p50 | p99 | dropped |
|---|---|---|---|---|
| default (workers × 8) | 4,938 qps | 166.2 ms | 171.9 ms | 24,899 |
| effectively unbounded | 5,851 qps | 978.8 ms | 989.5 ms | 0 |

A dropped query gets no answer at all, so it shows up as a client timeout rather than an error code.
